# Golden Touch — اللمسة الذهبية ✂️

نظام إدارة مواعيد خاص بصالون **Golden Touch**: يسجّل فيه الحلاق (المدير) ومشرف الحجوزات المواعيد من الموبايل، يمنع تداخلها تلقائياً، يسجّل المبلغ المدفوع لكل زبون، ويعرض إحصائيات أسبوعية وشهرية ولأي فترة.

> الموقع داخلي لفريق الصالون فقط (ليس للزبائن)، ولا يوجد تسجيل حسابات عام — **المدير وحده ينشئ الحسابات**.

## المزايا

| الميزة                      | التفاصيل                                                                                                                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **الجدول اليومي**           | خط زمني يعرض الحجوزات والأوقات المتاحة بتمييز بصري واضح (بطاقة بحد ملوّن = حجز، إطار ذهبي متقطع + زر "احجز" = وقت متاح)، مع مؤشر "الآن" وشريط أسبوع للتنقل بين الأيام                      |
| **منع التداخل**             | فحص في الخادم + قيد `EXCLUDE` في PostgreSQL يمنع حجزين متداخلين حتى لو أُرسلا في نفس اللحظة. الحجز من 4:00 إلى 5:00 يمنع أي حجز يبدأ قبل 5:00                                              |
| **حجز فوري ومجدول**         | لأي يوم قادم، مع شبكة أوقات تُظهر: متاح / محجوز (مخطط) / لا يتسع للمدة / مضى، ووقت مخصص للحالات الاستثنائية                                                                                |
| **حالات الحجز**             | قيد العمل ← مكتمل أو ملغي. الإلغاء يحرّر الوقت فوراً، مع زر "تراجع" وإعادة فتح                                                                                                             |
| **تسجيل الدفع**             | عند الإكمال يظهر حقل المبلغ وفيه سعر الخدمة افتراضياً، ويمكن تعديله لكل زبون                                                                                                               |
| **الخدمات والأسعار**        | المدير يضيف/يعدّل/يحذف/يرتّب الخدمات (السعر بالليرة السورية + مدة التنفيذ). الخدمة المرتبطة بحجوزات تُؤرشف بدل الحذف حفاظاً على السجل                                                      |
| **الزبائن**                 | يُنشأ الزبون تلقائياً من الحجز، مع بحث بالاسم/الهاتف، ملف لكل زبون (زياراته ومجموع ما دفعه)، اتصال وتذكير واتساب بنقرة                                                                     |
| **الإحصائيات**              | أسبوعي / شهري / فترة مخصصة: الدخل، عدد الزبائن، ساعات العمل، الحجوزات المكتملة، متوسط الفاتورة، نسبة الإلغاء، أكثر 3 زبائن، الخدمات الأكثر طلباً، أوقات الذروة — مع مقارنة بالفترة السابقة |
| **تنبيه الحجوزات المعلّقة** | الحجوزات التي انتهى وقتها ولم تُغلق تظهر في أعلى الجدول حتى تبقى الإحصائيات دقيقة                                                                                                          |
| **المستخدمون والصلاحيات**   | دوران: **المدير** (تحكم كامل) و**مشرف الحجوزات** (الحجوزات والزبائن والإحصائيات دون الأسعار والمستخدمين)                                                                                   |
| **إعدادات الصالون**         | ساعات الدوام (حتى بعد منتصف الليل)، دقة شبكة المواعيد، أيام العطلة، المنطقة الزمنية                                                                                                        |
| **Mobile-first**            | شريط تنقل سفلي مع زر حجز مركزي، أوراق سفلية (bottom sheets)، أهداف لمس ≥ 44px، ويمكن إضافته للشاشة الرئيسية كتطبيق (PWA manifest)                                                          |

## التقنيات

- **الواجهة** `apps/web`: Nuxt 4 (SSR) + Vue 3 + TypeScript، Pinia، Tailwind CSS 4، vee-validate + yup، خط Cairo عبر `@nuxt/fonts`، RTL عربي، ثيم فاتح فقط.
- **الخادم** `apps/api`: NestJS 11 + Prisma 6 + PostgreSQL (Supabase)، JWT في كوكي httpOnly، Swagger، throttling، helmet.
- **Monorepo** بـ npm workspaces. **لا يُستخدم Docker**.

## المتطلبات

- Node.js **22.18+** (مُختبر على 24) و npm 10+
- قاعدة بيانات Supabase (أو أي PostgreSQL 14+)

## التشغيل من الصفر

```bash
npm install
```

ثم املأ متغيرات البيئة (الملفات موجودة مسبقاً وفيها قيم جاهزة عدا كلمة مرور قاعدة البيانات):

1. `apps/api/.env` — ضع كلمة مرور قاعدة بيانات Supabase مكان `YOUR-DB-PASSWORD` في `DATABASE_URL` و `DIRECT_URL`
   (من Supabase ← Project Settings ← Database. إن احتوت رموزاً خاصة مثل `@ : / # ?` فيجب ترميزها percent-encode).
2. غيّر `SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD` لبيانات دخول المدير الأول إن أردت.

```bash
npm run db:migrate
```

```bash
npm run db:seed
```

```bash
npm run dev
```

- الواجهة: http://localhost:3000
- الـ API: http://localhost:4000/api — التوثيق (Swagger): http://localhost:4000/api/docs
- الفحص الصحي: http://localhost:4000/api/health

> بعد الدخول الأول: افتح **الخدمات والأسعار** وحدّد سعر كل خدمة (الـ seed ينشئ: شعر، ذقن، شعر وذقن، سشوار بسعر 0)، ثم أنشئ حساب مشرف الحجوزات من **المستخدمون**.

## الأوقات والمنطقة الزمنية

كل الأوقات تُخزَّن UTC، وتُحسب "الأيام" وساعات الدوام والإحصائيات بتوقيت الصالون (`Asia/Damascus` افتراضياً، قابل للتغيير من الإعدادات) — فالنتائج صحيحة مهما كان توقيت الخادم أو جهاز المستخدم.

## إضافة وحدة جديدة (مثال: "المصاريف")

**الـ Backend**

1. أضف الموديل في `apps/api/prisma/schema.prisma` ثم: `npm run db:migrate:dev -- --name expenses`.
2. أنشئ `apps/api/src/modules/expenses/` بنفس نمط `services/`: `dto/` (class-validator برسائل عربية + Swagger decorators)، `expenses.service.ts`، `expenses.controller.ts` (`@ApiTags`، `@ApiCookieAuth`، `@RequirePermissions('expenses.read')`…)، `expenses.module.ts`.
3. سجّل الوحدة في `src/app.module.ts`.
4. أضف الصلاحيات `expenses.read/create/update/delete` في `prisma/seed.ts` (ولدور staff إن لزم) ثم `npm run db:seed`.

**الواجهة**

1. أضف الأنواع في `app/types/api.ts`.
2. أنشئ `app/stores/expenses.ts` (إن احتاجت حالة مشتركة) أو استخدم `useApiState` مباشرة في الصفحة.
3. أنشئ `app/pages/expenses.vue` مع `definePageMeta({ permission: 'expenses.read' })`، وحوار `components/expenses/ExpenseFormDialog.vue` (حالة الفتح محلية في الصفحة).
4. أضف العنصر في `app/config/navigation.ts` مع مفتاح الصلاحية وموضعه (`sidebar` / `more`).
5. قيّد الأزرار بـ `v-perm="'expenses.create'"` أو `usePermission().has(...)`.

## النشر على Render (الخطة المجانية)

المشروع يُنشر كـ **خدمة ويب واحدة** على Render بلا Docker، والإعدادات كلها في [render.yaml](render.yaml):

- `scripts/start-prod.mjs` يشغّل الواجهة على المنفذ العام الذي يحدده Render، والـ API داخلياً على `127.0.0.1:4000`، والواجهة تمرّر له `/api/**`.
- المنطقة **Ohio** = نفس منطقة قاعدة البيانات على Supabase (us-east-2) فيكون الاتصال بينهما شبه فوري.
- الخطة المجانية لا تدعم Pre-Deploy، لذا تُطبَّق الـ migrations ضمن أمر البناء.

### إبقاء الخادم مستيقظاً (مهمة دورية كل 10 دقائق)

الخطة المجانية تُطفئ الخادم بعد **15 دقيقة** بلا طلبات، وأول فتحة بعدها تتأخر قرابة دقيقة.
لذلك يحتوي الـ API على مهمة دورية (`apps/api/src/modules/health/keep-alive.service.ts`) تطلب
`<رابط الموقع>/api/health` **كل 10 دقائق** عبر الرابط العام (`RENDER_EXTERNAL_URL` الذي يضبطه Render تلقائياً):

- الطلب يمر من موازن Render فيُحسب كحركة واردة فلا يُطفأ الخادم.
- `/api/health` يستعلم قاعدة البيانات، فيبقى مشروع Supabase المجاني نشطاً أيضاً (يُوقَف بعد أسبوع خمول).
- يظهر في Logs على Render سطر `Keep-alive ok` كل 10 دقائق للتأكد أنها تعمل.
- المدة قابلة للتغيير بـ `KEEP_ALIVE_INTERVAL_MINUTES` (من 1 إلى 14). محلياً المهمة معطّلة.

> الخطة المجانية تمنح 750 ساعة تشغيل شهرياً، وخدمة واحدة تعمل طوال الشهر تستهلك ~744 ساعة — أي تكفي لخدمة واحدة فقط على نفس الحساب.

### الخطوات

1. ارفع المشروع إلى مستودع **خاص (Private)** على GitHub. ملفات `.env` لا تُرفع (مستثناة في `.gitignore`).
2. على [render.com](https://render.com): **New ← Blueprint** واختر المستودع؛ سيقرأ `render.yaml` تلقائياً.
3. سيطلب Render قيمتي `DATABASE_URL` و `DIRECT_URL` — انسخهما كما هما من `apps/api/.env`. (`JWT_SECRET` يُولَّد تلقائياً.)
4. اضغط **Apply**. البناء يستغرق بضع دقائق، ثم يصبح الموقع على رابط مثل `https://golden-touch.onrender.com`.
5. افتح الرابط من هاتف الحلاق ← قائمة المتصفح ← **إضافة إلى الشاشة الرئيسية**.

كل `git push` لاحق يعيد النشر تلقائياً. لا حاجة لـ `db:seed` على Render (البيانات الأساسية موجودة في قاعدة البيانات).
