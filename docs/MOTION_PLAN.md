# خطة الحركة السلسة (Smooth Motion) — Golden Touch

**الهدف:** كل انتقال بين الصفحات، وكل ظهور واختفاء لأي عنصر، وكل إجراء (نقر، تبديل، حفظ، حذف، فلترة…) يتم بحركة سلسة، دون أي تبديل فجائي.

**طريقة العمل:** 7 مراحل. أُنفّذ مرحلة كاملة، أشغّل الفحص (`lint → typecheck → test → build`)، أُحدّث «سجل التقدّم» أسفل الملف، **ثم أتوقف** وأنتظر أمرك بالبدء بالتالية. لا commit ولا push من طرفي.

---

## 1. مبادئ الحركة (تُطبَّق في كل المراحل)

| #   | القاعدة                                                                                                                                         | السبب                   |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| R1  | تحريك `transform` و`opacity` فقط. الارتفاع يُحرَّك عبر مكوّنين مخصصين (`Collapse`, `ExpandTransition`, لاحقاً `AutoHeight`) لا مباشرة.          | أداء 60fps على الموبايل |
| R2  | لا `v-if`/`v-else`/`v-show` يغيّر شيئاً مرئياً دون انتقال («لا تبديل عارٍ»).                                                                    | شرط «بلا استثناء»       |
| R3  | الخروج أسرع من الدخول (≈ 65%).                                                                                                                  | الواجهة تبدو مستجيبة    |
| R4  | لا حركة عند الـ hydration (لا `appear` على محتوى الصفحة)، والتحديث الصامت (كل 60ث) لا يعيد تشغيل أي حركة.                                       | تجنّب الوميض            |
| R5  | `prefers-reduced-motion`: تختفي الإزاحة والتكبير (تبقى تلاشيات قصيرة)، وتقفز الحركات البرمجية للقيمة النهائية، ويبقى مؤشر التحميل الدوّار يدور. | الإتاحة                 |
| R6  | اتجاه الحركة يتبع RTL (متغيّر `--dir-end`): «التالي» يدخل من جهة النهاية.                                                                       | الواجهة عربية           |
| R7  | كل حركة قابلة للمقاطعة (نقر سريع متكرر لا يكسرها) — لذلك transitions/WAAPI لا keyframes للتبديلات.                                              | استقرار                 |
| R8  | لا قفزة تخطيط (CLS): العنصر المغادر يُثبَّت مكانه، والـ `gap` المحيط يُعوَّض.                                                                   | سلاسة بصرية             |
| R9  | لا تغيير في الألوان ولا التباين، و`aria-live` والتركيز يبقيان سليمين.                                                                           | قواعد الإتاحة           |
| R10 | ممنوع `transition: all`، و`will-change` مؤقت فقط.                                                                                               | أداء                    |
| R11 | ألوان وتباين وأحجام الخطوط **لا تُمَسّ** (قاعدة ضعاف البصر).                                                                                    | قاعدة المستخدم          |

**الرموز (tokens):** مدد `instant 100 / fast 150 / base 220 / slow 320 / page 260ms`. منحنيات: `out` (الموجود `--ease-out-soft`) للدخول، `in` للخروج، `in-out` للتحريك، `spring` للنقرات الصغيرة فقط. مصدر واحد للقيم في CSS و`app/utils/motion.ts` مع اختبار يضمن تطابقهما.

**الأدوات:** CSS transitions + `<Transition>`/`<TransitionGroup>` + Web Animations API. لا مكتبات (التزاماً بقواعد المشروع).

## 2. حدود ما لا يمكن تحريكه (للشفافية)

عناصر يرسمها المتصفح/النظام ولا سيطرة لنا عليها:

- قائمة `<select>` المنسدلة، ومنتقيات `input[type=date|time]` (واجهة النظام).
- شريط التمرير، وحركة زر الرجوع/السحب في المتصفح، وفتح `tel:` و`wa.me`.

**التعامل:** نُبقيها أصلية عمداً لأنها الأفضل على الموبايل (لوحات النظام المألوفة). في المرحلة 5 أعرض عليك — فقط إن رغبت — استبدال `AppSelect` بقائمة مخصصة قابلة للتحريك (تكلفتها أعلى وتحتاج عناية إتاحة).

## 3. المراحل

### المرحلة 1 — الأساسات + أول المستهلكين

**النطاق:** رموز الحركة، سياسة reduced-motion، سلاسة التفاعلات الصغيرة في كل التطبيق، والمكوّنان الأساسيان لإظهار/إخفاء الارتفاع.

1. **`main.css`**
   - رموز: مدد `--motion-*`، منحنيات `--ease-in-soft/--ease-in-out-soft/--ease-spring`، `--dir-end`، `--motion-distance`.
   - **إصلاح خلل قائم:** قاعدة reduced-motion الحالية تُوقف `animate-spin` فيختفي مؤشر التحميل؛ تُستبدل بسياسة R5.
   - `scrollbar-gutter: stable` (قفل التمرير عند فتح الحوار لا يُزيح الصفحة).
   - انتقال افتراضي ناعم لكل `a/button/input/select/textarea/summary` (لونا/حدود/ظل/شفافية/transform) يُلغيه أي `transition-*` صريح.
   - حلقة التركيز تتمدّد بسلاسة بدل الظهور الفجائي.
2. **`utils/motion.ts`** (ثوابت + `prefersReducedMotion`) و**`composables/useReducedMotion.ts`** + اختبارات.
3. **`ui/ExpandTransition.vue`** — لعناصر `v-if` (ارتفاع + شفافية + هوامش + تعويض `gap` الأب) عبر WAAPI، قابل للمقاطعة.
4. **`ui/Collapse.vue`** — لقوائم/أقسام مفتوحة-مغلقة (`grid-template-rows`)، مع `inert` عند الإغلاق.
5. **حقول الإدخال:** `AppInput/AppSelect/AppTextarea` — حلقة التركيز (`box-shadow`) تُحرَّك.
6. **أول المستهلكين (إثبات الأساسات):**
   - `FormField`: ظهور/اختفاء رسالة الخطأ والتلميح (يشمل كل نماذج التطبيق).
   - `DayAgenda`: قسم «حجوزات ملغاة» → `Collapse`.
   - `OverdueBanner`: ظهور/اختفاء اللافتة + «عرض الكل/أقل».

**القبول:** لا قفزات عند ظهور خطأ تحقق؛ طيّ/فتح الملغاة سلس؛ spinner يعمل مع reduced-motion؛ الفحص الشامل أخضر.

### المرحلة 2 — الصفحات والتخطيطات والتنقل

1. `nuxt.config`: `pageTransition` و`layoutTransition` (out-in، قصيرة).
2. **اتجاه ذكي** (`utils/route-motion.ts` + plugin): أعمق ⇐ يدخل من النهاية، أقل ⇐ من البداية، نفس المستوى (تبويبات) ⇐ تلاشٍ؛ يراعي زر الرجوع عبر `history.state.position` وRTL.
3. **تخطيط**: دخول/خروج `default ↔ auth` (تسجيل الدخول/الخروج)، و`error.vue`.
4. **التمرير:** `router.options` — العودة للأعلى بسلاسة بعد الانتقال، واستعادة الموضع عند الرجوع.
5. **التنقل:** مؤشر منزلق للتبويب النشط في `BottomNav`/`NavTab`، ومؤشر منزلق في `AppSidebar`، وتحريك زر «حجز» المركزي، و`AppHeader`.
6. `PageHeader` (تبدّل العنوان من هيكل التحميل إلى الاسم)، `NuxtLoadingIndicator`.
7. إدارة التركيز بعد الانتقال (`#main`) دون كسر الحركة.
8. التحقق من أن كل صفحة ذات عنصر جذر واحد (شرط Nuxt).

**القبول:** كل انتقال بين الصفحات (طرفيات، عميق، رجوع، تسجيل خروج/دخول، 404) سلس وباتجاه صحيح.

### المرحلة 3 — الحوارات والأوراق والإشعارات

1. **`AppModal`:** تلاشي الخلفية + ورقة تصعد/تهبط (موبايل) وتكبير ناعم (سطح مكتب) **مع حركة خروج** (غائبة حالياً)، قفل التمرير بلا إزاحة، إعادة التركيز.
2. **سحب للإغلاق** (swipe-down) للورقة السفلية على الموبايل مع ارتداد.
3. **`AutoHeight`** (جديد): ارتفاع الحوار يتغيّر بسلاسة عند تبدّل المحتوى.
4. **`BookingSheet`:** انتقال بين الأوضاع (تفاصيل ⇄ إكمال ⇄ إلغاء ⇄ تعديل مبلغ) للمحتوى **وأزرار التذييل**، ظهور شريط الخطأ، تبدّل شارة الحالة.
5. **`ConfirmDialog`** (تبدّل العنوان/النص دون وميض)، و`CustomerFormDialog/ServiceFormDialog/UserFormDialog` (شريط خطأ الخادم، وصف الدور، حقل كلمة المرور).
6. **`ToastViewport`:** دخول/خروج مناسبان، **إعادة ترتيب سلسة** عند اختفاء إشعار، سحب للإخفاء، ثبات الموضع.
7. `useToast`/`useConfirm`: ضمان عدم إزالة المحتوى قبل نهاية حركة الخروج.

**القبول:** فتح/إغلاق كل حوار سلس بالاتجاهين، وتبدّل أوضاع ورقة الحجز بلا قفزة ارتفاع.

---

### المرحلة 4 — الحالات والقوائم والبيانات

1. **`ListTransition`** (جديد: `TransitionGroup` مع تثبيت العنصر المغادر وFLIP للحركة).
2. **`FadeTransition`** (جديد) + **تبديل حالات** `LoadingState → المحتوى / ErrorState / EmptyState` بتلاشٍ.
3. **`useApiState`:** تمييز «تحميل أول/تغيير مفتاح» عن «تحديث صامت» لعدم وميض `opacity` كل 60 ثانية.
4. **`pages/index` + `DayAgenda`:** تبدّل اليوم باتجاه الأسبوع، إضافة/إزالة/تحريك البطاقات (حجز يتحوّل إلى فراغ والعكس)، مؤشر «الآن»، ملخص اليوم، لافتة الأسعار.
5. **`DateStrip`:** مؤشر اليوم المحدّد منزلق، انزلاق الأسبوع، تبدّل اسم الشهر، ظهور زر «اليوم».
6. **`bookings/index`:** مجموعات اليوم، تغيّر النتائج مع البحث/الفلاتر، حقول الفترة (`Collapse`)، `SegmentedControl` (مؤشر منزلق)، شرائح الحالة.
7. **`customers/index`, `customers/[id]`, `users/index` (`DataTable`), `services`:** إضافة/حذف/ترتيب الصفوف (ترتيب الخدمات بالأسهم حالياً فجائي)، `AppPagination` (تبدّل الصفحات).
8. `GapCard`, `BookingCard`: انتقال حالات (فراغ ⇄ حجز، ملغى، «الآن»).

**القبول:** لا تبديل فجائي في أي قائمة/حالة؛ التحديث الصامت لا يُرى.

---

### المرحلة 5 — النماذج والمدخلات

1. **استبدال `<details>`** (في `BookingForm` و`SlotPicker`) بـ `Disclosure` مبني على `Collapse` مع الحفاظ على الإتاحة.
2. **`BookingForm`:** شريط الخطأ، شريط الملخص السفلي (تبدّل النص/السعر)، التواريخ السريعة، تبدّل الخطوات، التمرير السلس لأول خطأ (موجود، يُراجَع).
3. **`SlotPicker`:** التحميل ⇄ الشبكة، المجموعات الزمنية، تبدّل حالة الخانة، «الأوقات الماضية»، حالة «لا أوقات»، بطاقة الإغلاق الأسبوعي.
4. **`CustomerPicker`:** تبدّل «زبون مختار ⇄ حقول»، لوحة الاقتراحات (ظهور/قائمة).
5. **`ServicePicker`:** علامة الاختيار، تبدّل الألوان.
6. **`AppButton`:** تبدّل الأيقونة ⇄ المؤشر (بلا تغيّر عرض مفاجئ)، `AppSwitch`, `SearchInput` (زر المسح)، إظهار/إخفاء كلمة المرور (تبدّل الأيقونة)، `AppMoneyInput`.
7. **`pages/settings`** (أيام العطلة، تنبيه الدوام الليلي، زر الحفظ الثابت يُفعَّل بسلاسة)، `login`, `account`, `more`.
8. `UserFormDialog` (وصف الدور)، `ServiceFormDialog` (شرائح المدة).
9. قرار اختياري: قائمة مخصصة بدل `<select>` (انظر §2).

**القبول:** كل ظهور/اختفاء داخل نموذج سلس؛ لا قفزة عند الحفظ أو الخطأ.

---

### المرحلة 6 — البيانات والرسوم والتفاصيل الدقيقة

1. **`AnimatedNumber`** (جديد) — عدّ تصاعدي للمبالغ/الأرقام (مع `Intl` الموجود وreduced-motion): `StatCard`، ملخص اليوم، شريط سعر `BookingForm`، إحصاءات الزبون.
2. **`BarChart`:** نمو الأعمدة عند أول عرض وعند تغيّر البيانات (تدرّج خفيف)، تبدّل العمود المحدّد وملخصه.
3. **`pages/stats`:** تبدّل الفترة (قديم → جديد)، أشرطة «الخدمات الأكثر طلباً» (`scaleX`)، قوائم الأكثر زبائن، شارات الاتجاه.
4. `StatusBadge/AppBadge`، `EmptyState/ErrorState` (دخول أيقونة)، `AppSpinner`, الهيكل العظمي `skeleton`.
5. تأثيرات التمرير فوق البطاقات (`hover` على أجهزة المؤشر فقط) وضغطها على اللمس.
6. نبض «الآن» (`animate-pulse`) والنقطة الحمراء.

**القبول:** أرقام ومخططات تتحرك بسلاسة وتحترم reduced-motion.

---

### المرحلة 7 — التدقيق الشامل والتوثيق

1. **مسح آلي** لكل `v-if/v-else/v-show` وكل `transition-*` المنقوص (grep + قائمة تحقق ملفاً ملفاً من §4).
2. اختبار reduced-motion يدوياً، وRTL، وiOS Safari / Chrome Android / Firefox / Chrome سطح المكتب.
3. أداء: لا `transition: all`، لا layout thrash، `will-change` مؤقت، فحص مسار الرسم.
4. اختبارات وحدة للمنطق النقي (اتجاه الانتقال، الـ easing، تطابق الرموز).
5. توثيق «اتفاقيات الحركة» في `CLAUDE.md` (الرموز، المكوّنات، القواعد R1–R11).
6. فحص شامل نهائي: `npm run lint && npm run typecheck && npm test && npm run build`.

**القبول:** صفر عناصر بلا انتقال في قائمة §4، والفحص أخضر.

## 5. بروتوكول كل مرحلة

1. تنفيذ كامل المرحلة دون اختصار (لا تأجيل بنود لمرحلة لاحقة إلا ما هو مذكور أعلاه).
2. `npm run lint && npm run typecheck && npm test && npm run build`.
3. فحص دخان: تشغيل الواجهة والتأكد من عدم وجود أخطاء SSR/hydration.
4. تقرير بما تغيّر + **قائمة فحص يدوي** تجرّبها بنفسك في المتصفح (لأن الحركة لا تُثبت بالفحص الآلي وحده).
5. **توقف** حتى تطلب المرحلة التالية.
