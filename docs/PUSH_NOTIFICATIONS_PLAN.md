# دراسة: إشعار المدير قبل موعد الزبون — Golden Touch

**المطلوب:** إشعار على هاتف المدير قبل بداية كل موعد بـ 15 دقيقة: «أحمد العلي · قص شعر · 4:30 م». لا شيء غيره.

**الأجهزة:** المدير على **Poco** (Xiaomi، Android — **مؤكَّد من المدير**؛ يبقى إصدار HyperOS/MIUI وChrome وخدمات Google للتحقق في المرحلة 0)، وبقية المستخدمين على Android. الموقع يُستعمل من المتصفح لا كتطبيق متجر. **iPhone غير مستعمل حالياً**؛ بنوده في الخطة احتياط إن تغيّر الجهاز.

**الحالة:** المرحلة 0 نُفّذت ونجحت على Poco (وصل الإشعار بعد ثوانٍ وسُمع الصوت). **المرحلتان 1 (الخادم) و2 (الواجهة) مكتوبتان ومفحوصتان محلياً ولم تُنشرا بعد.** بقيت المرحلة 3: النشر وحجز تجريبي بعد 17 دقيقة **بموافقة صريحة**. لا `git add/commit/push` إلا بطلب صريح. قواعد `CLAUDE.md` سارية.

**المرحلة 0 (أُزيلت بعد المرحلة 2):** كانت وحدة `push-lab` مؤقتة في الـ API وصفحة `/push-lab` بلا قاعدة بيانات لتجربة الوصول والصوت على Poco؛ حلّت محلها واجهة الحساب (`PushSettings`) والمسارات `/push/*`.

## 1. الخلاصة

**ممكن ومجاني بالكامل** عبر **Web Push** القياسي (Push API + Service Worker + مفاتيح VAPID). على **Poco (Android)** لا شرط تثبيت؛ **الخطر الوحيد الجدّي إدارة البطارية في Xiaomi** (§4) ويُعالَج بإعداد لمرة واحدة على هاتف المدير. (على iPhone، لو تغيّر الجهاز: إضافة الموقع إلى الشاشة الرئيسية شرط.)

- **Poco / Xiaomi (جهاز المدير):** Chrome يستقبل Push عبر FCM والموقع مغلق، دون تثبيت. واجهات Xiaomi تقتل التطبيقات الخلفية بشدة وقد تؤخّر الإشعار أو تمنعه، فالإعداد المطلوب: Chrome (أو التطبيق المثبَّت) ← توفير البطارية «بلا قيود» + «التشغيل التلقائي» مفعّل + قفل التطبيق في قائمة الأحدث. يُنصح بتثبيته «كتطبيق» (Chrome ← تثبيت التطبيق) لتكون له إعدادات بطارية وإشعارات مستقلة. يُقاس كله في المرحلة 0.
- **iPhone (احتياط، iOS 16.4+):** Apple لا تسمح بالإشعارات لتبويب Safari العادي، بل لـ«تطبيق الويب» المضاف إلى الشاشة الرئيسية فقط. الموقع جاهز لذلك أصلاً (`manifest.webmanifest` بوضع `standalone`، `apple-touch-icon`، أزرار رجوع داخلية في `PageHeader` وشريط سفلي). **لا يلزم حساب Apple Developer** (توثيق Apple).
- **Android:** يعمل في Chrome للموقع العادي دون تثبيت.
- **كود خادم واحد للمنصتين:** نفس المكتبة (`web-push`) ونفس المفاتيح؛ المتصفح يحدّد خدمة التوصيل (APNs من Apple / FCM من Google) مجاناً.
- **بلا Firebase ولا طرف ثالث**، و**المحتوى مشفّر طرفياً** (RFC 8291): Apple وGoogle توصلان الرسالة ولا تقرآن اسم الزبون.
- لا يغيّر بنية الحجوزات: جدول اشتراكات + عمود واحد + حلقة كل دقيقة بنمط `RecurringSyncService` + ملف `sw.js` صغير.
- الكلفة: 0. الجهد: نحو 3 أيام عمل.

**ما لا يُحسم بالكود:** سلوك بطارية Poco مع Chrome في الخلفية، ووجود خدمات Google على الهاتف، والتوصيل الفعلي من سوريا. لذلك **المرحلة 0 تجربة على هاتفه قبل أي بناء** (§8).

## 3. كيف يعمل

```
[هاتف المدير]                           [Render: NestJS]               [APNs / FCM]
 0. (Poco) تسجيل الدخول في Chrome + إعداد البطارية؛ (iPhone فقط) إضافة للشاشة الرئيسية
 1. «تفعيل الإشعارات» (نقرة)
    Notification.requestPermission()
    pushManager.subscribe(VAPID public)
 2. POST /api/push/subscriptions ─────▶ يحفظ endpoint + مفاتيح
                                         3. كل 60ث: حجوزات تبدأ خلال 15د
                                            ولم يُشعَر بها → حجز ذرّي
                                         4. web-push (مشفّر، Urgency: high،
                                            TTL = حتى بداية الموعد) ──────────▶ 5. يوقظ الهاتف
 6. sw.js: showNotification() ◀───────────────────────────────────────────────────┘
 7. نقرة → فتح التطبيق على أجندة اليوم
```

## 5. التصميم

### 5.1 البيانات (migration إضافية فقط — آمنة على الإنتاج، مع `docs/PUSH_NOTIFICATIONS_ROLLBACK.sql`)

```prisma
model PushSubscription {
  id         String   @id @default(uuid()) @db.Uuid
  userId     String   @db.Uuid
  user       User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  endpoint   String   @unique
  p256dh     String
  auth       String
  userAgent  String?  // لعرض «iPhone» / «Chrome · Android» في قائمة الأجهزة
  lastSeenAt DateTime @default(now()) @db.Timestamptz(3) // يُحدَّث عند فتح التطبيق
  createdAt  DateTime @default(now()) @db.Timestamptz(3)
  @@index([userId])
  @@map("push_subscriptions")
}

// في Booking:
/// وقت إرسال إشعار «يبدأ بعد 15 دقيقة» للطاقم — منفصل عن تذكير الزبون (واتساب)
startAlertSentAt DateTime? @db.Timestamptz(3)
```

- لا حاجة لتعبئة الحجوزات القديمة: الاستعلام لا ينظر إلا لما يبدأ خلال الدقائق القادمة.
- **`toBookingView` ينشر الحجز كاملاً (`...rest`)**: احذف `startAlertSentAt` منه (أو `omit` في Prisma) كي لا يدخل استجابات الـ API ولا يخالف Swagger.

### 5.2 المُرسِل — `modules/push/` (نمط `RecurringSyncService`)

حلقة كل 60ث (معطّلة في `NODE_ENV=test` وبـ `PUSH_ALERT_MINUTES=0`)، والمنطق النقي في `push-alert.calc.ts` مع اختبارات:

| القاعدة | التفصيل |
| --- | --- |
| المستحق | `status = ACTIVE` و`startAlertSentAt IS NULL` و`now + 1د < startAt ≤ now + 15د` (فهرس `[status, startAt]` موجود). |
| حجز أُنشئ داخل النافذة | يُتخطّى: `createdAt > startAt − 15د` — قرار D2. |
| منع التكرار | قبل الإرسال: `updateMany({ where: { id, startAlertSentAt: null, startAt }, data: { startAlertSentAt: now } })`؛ يُرسَل فقط إن `count === 1`. مرة واحدة على الأكثر حتى مع نسختين أثناء النشر. |
| تغيير موعد الحجز / إعادة فتحه | `BookingsService.update()` عند تغيّر `startAt`، و`reopen()`: `startAlertSentAt = null`. |
| التدارك بعد توقف | أي مستحق لم يُرسَل يُرسَل فوراً بالدقائق الفعلية («بعد 6 دقائق»)؛ بعد البداية لا شيء. |
| المستلمون | اشتراكات مستخدمين `isActive` يملك دورهم الصلاحية (D1)، و`lastSeenAt` خلال 30 يوماً (= عمر الجلسة `JWT_EXPIRES_IN`). |
| خيارات الإرسال | `Urgency: high`، `TTL` = الثواني حتى بداية الموعد (≥ 60). |
| الردود | `404/410` ← حذف الاشتراك. `403` ← تحذير في السجل (خطأ مفاتيح، لا يُحذف شيء). `5xx`/شبكة ← محاولة واحدة فورية ثم تسجيل. |
| السجل | أعداد فقط: `Push alerts: due=2 sent=2 removed=0` — بلا أسماء ولا هواتف. |
| الحجوزات المتعددة | إشعار لكل حجز بـ `tag = booking-<id>`. |

**المحتوى:** العنوان «موعد بعد 15 دقيقة»، النص «الاسم · الخدمة · 4:30 م» (عبر `formatTime` بتوقيت الصالون). **لا سعر ولا هاتف ولا أي حقل مالي.**

### 5.3 الـ API

| المسار | الوصف |
| --- | --- |
| `GET /push/public-key` | مفتاح VAPID العام. |
| `POST /push/subscriptions` | تسجيل/تحديث اشتراك الجهاز (upsert على `endpoint`؛ ينقل الملكية للمستخدم الحالي ويحدّث `lastSeenAt`). |
| `DELETE /push/subscriptions` | `{ endpoint }` — إيقاف على هذا الجهاز (وعند تسجيل الخروج). |
| `POST /push/test` | إشعار تجريبي لأجهزة المستخدم الحالي (`@Throttle` 5/دقيقة). |

- **الأمان (SSRF):** الخادم يرسل POST لعنوان يقدّمه المستخدم؛ اقبل `https` فقط ومضيفاً من قائمة: `*.push.apple.com`، `fcm.googleapis.com`، `*.push.services.mozilla.com`، `*.notify.windows.com`. رسائل التحقق بالعربية.
- **المفاتيح:** `VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` في متغيرات Render (`sync: false`)، تُولَّد مرة واحدة (`npx web-push generate-vapid-keys`) — **تغيير المفتاح الخاص يبطل كل الاشتراكات** (Apple: `VapidPkHashMismatch`). مفاتيح مختلفة للتطوير. `VAPID_SUBJECT` = رابط الموقع (لا بريد شخصي). بدون المفاتيح: الميزة معطّلة بهدوء ولا تمس الإقلاع.
- **المكتبة:** `web-push` (MIT، نسخة محددة بلا `^`) — التشفير (aes128gcm + ECDH) وتوقيع VAPID لا يُكتبان يدوياً.

### 5.4 الواجهة

- **`apps/web/public/sw.js`** (~30 سطراً، بلا مكتبات): `push` ← `showNotification` **دائماً** (نص احتياطي إن فشل التحليل — شرط Apple)، أيقونة `icon-192.png`، `dir: 'rtl'`, `lang: 'ar'`, `tag`؛ و`notificationclick` ← تركيز نافذة مفتوحة أو فتح `/`. **بلا مستمع `fetch` ولا كاش** كي لا يمس SSR أو `back-stack`. `cache-control: no-store` القائم يضمن تحديثه.
- **`composables/usePush.ts`** — الحالات:
  - `needs-install` (iPhone فقط؛ لا يظهر على Poco): iPhone في Safari غير مضاف (`!matchMedia('(display-mode: standalone)').matches` و`PushManager` غير متاح).
  - `unsupported` / `denied` / `off` / `on`.
  - `enable()` و`disable()` و`test()`؛ وعند فتح التطبيق إن كان الإذن ممنوحاً: تحديث `lastSeenAt`، أو **إعادة الاشتراك تلقائياً** إن ضاع.
- **`pages/account.vue` — قسم «الإشعارات على هذا الجهاز»:**
  - `needs-install`: خطوات مرقّمة بأيقونات: مشاركة ← «إضافة إلى الشاشة الرئيسية» ← افتح Golden Touch من الأيقونة وسجّل الدخول.
  - `off`: زر «تفعيل الإشعارات». `on`: «إشعار تجريبي» و«إيقاف».
  - `denied`: خطوات فك الحظر (iPhone: الإعدادات ← الإشعارات ← Golden Touch؛ Android: إعدادات الموقع في Chrome).
  - على Android: خطوات قصيرة لمرة واحدة (البطارية «بلا قيود»، التشغيل التلقائي، قفل التطبيق، وإشعارات Chrome «أهمية عالية + صوت مفعّل») — تُعرض أولوية على Xiaomi/Poco (كشف من `userAgent`/`Build` إن أمكن، وإلا تُعرض لكل Android). (iPhone: وضع التركيز.)
- **تسجيل الخروج:** `unsubscribe()` + `DELETE` قبل `/auth/logout` — جهاز مشترك لا يستمر باستقبال أسماء الزبائن.
- قواعد التباين والحركة وRTL و44px كالمعتاد.
